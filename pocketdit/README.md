# PocketDiT

一个精简的、基于口袋的分子对接模型：**Pocket-conditioned Geometric DiT + Flow Matching**。
完全独立于上一级目录的 `sigmadock`（不 import 它的任何代码），只依赖 `torch`、`numpy`、`rdkit`。

```
pocketdit/
  chem.py    PDB/SDF 解析、口袋提取、配体与口袋特征化              ~220 行
  fragment.py 刚性片段分解（切可旋转键 + 合并），尚未接入模型       ~310 行
  rigid.py   每个片段的 SE(3) 目标（对齐模板 + 等价解消歧），尚未接入模型 ~400 行
  data.py    预处理成 .pt 缓存、Dataset、padding 批处理              ~160 行
  model.py   静态口袋编码器 + Geometric DiT + 等变输出头              ~260 行
  flow.py    先验、插值路径、损失、Euler 采样器                       ~85 行
  train.py   纯 PyTorch 训练循环（AdamW、warmup+cosine、EMA、bf16）    ~200 行
  dock.py    推理命令行，输出 SDF                                     ~120 行
tests/       等变性、padding、采样器、单复合物过拟合、端到端命令行
```

## 模型

```
Protein Pocket ──► PocketEncoder（静态，与 t 和配体位姿无关；采样时只算一次）──► h_p
                                                                                │
Ligand 分子图 + x_t ──► Atom Embedding ──► Geometric DiT × depth ──► Geometric Head ──► x̂_1
                                              ├ Ligand Self-Attention   bias: RBF(d_ij(x_t)) + 键类型 + 拓扑距离
                                              ├ Pocket Cross-Attention  bias: RBF(d_ik(x_t, 口袋原子))
                                              ├ MLP
                                              └ adaLN-Zero（flow time t 调制三个子层）
```

- **Token**：配体每个重原子一个 token；口袋是**按距离排序、整残基选取、截到 256 个原子**的重原子集合（见下文"口袋预算"）。
- **几何只通过注意力 bias 进入主干**：用 `F.scaled_dot_product_attention` 的加性 mask 实现，主干几乎全是稠密矩阵乘法，没有 PairFormer 和 triangle 操作。
- **输出头**：`Δx_i = mean_j w_ij·r̂_ij + mean_k w_ik·r̂_ik`，其中 w 是不变标量，r̂ 是相对向量，所以 `x̂_1 = x_t + Δx` 在构造上就是 SE(3) 等变的，不需要旋转数据增强。
- **手性**：只看距离的模型分不清镜像，生成时会翻转手性中心。所以给每个立体中心加一个特征 `sign · 有向体积(x_t)`：它在旋转下不变，在镜像下变号。参考符号取自输入的 3D 构象，避开了 RDKit 中 CW/CCW 邻居顺序的约定。这样模型是 SE(3) 而不是 E(3) 等变的，有测试覆盖。
- adaLN-Zero 和输出头都是零初始化：初始化时模型恒等输出 `x̂_1 = x_t`。

## 口袋预算

缓存时按 15 Å 存下最宽的那一层壳（约 1300 个原子 / 90 KB per 复合物），加载每个复合物时再裁到预算（`data.PocketCrop`）。缓存留的余量是给参考配体扰动用的，必须覆盖 `PocketCrop.cache_cutoff_needed(ref_radius)`，否则扰动后的壳会在那一侧被悄悄切掉。注意这个需求**随配体自身半径变化**（旋转把距质心 `r` 的原子甩出 `2·sin(θ/2)·r`），所以每个复合物加载时都精确检查一次，不够就报错并给出该用的 `--pocket_cutoff`。

- **只按整残基选，按残基到参考配体的最小距离排序。** 4 Å 以内的是接触壳，优先保留；其余按从近到远填满预算。
- **4 Å 核心 + 不设 cutoff 单靠 256 预算填**，在 10 个示例复合物上等效 cutoff 自己就落在平均 **6.5 Å**（范围 5.8–6.9）—— 而这正是 SigmaDock 训练用的口袋尺度（`pocket_distance_cutoff: 6.0` + `pocket_distance_noise: 0.5`）。所以 `cutoff` 默认取 6.5：两个控制量互相印证，实测下来两者都会生效（约 4 个复合物先碰到预算，约 6 个先碰到 cutoff），最终 **203–253 个原子 / 等效 5.8–6.5 Å**，对比 8 Å 整壳的 348–444 个。
- 显存上，10 个复合物一个 batch：`PocketEncoder` 里 `[B,M,M,16]` 的 RBF 从 126 MB 降到 41 MB，`z_lp` 的 `[B,N,M,64]` 从 40 MB 降到 23 MB。
- 半个残基对 `ATOM_NAMES` / `RESIDUES` 嵌入是分布外的（没有 CA 的骨架 N、苯环的三个碳），所以不做原子级选取；按距离截断也优于在 4–8 Å 带里均匀采样 —— 后者会留下 7.9 Å 的原子而丢掉 4.1 Å 的。
- 顺带的收益：输出头把口袋项按 `n_p` 取平均，400 个大多很远的原子会把约 37 个真实接触稀释 10 倍，而 `n_p` 在不同复合物间从 126 变到 600 又会让这一项的尺度跟着变。
- **预算是上限不是配额。** 小而深的口袋就保持小，不会用溶剂暴露的残基填到 256；核心本身超预算时丢掉它最远的残基，大配体退化成最近的接触而不是整条样本作废。
- **随机性加在边界上，不加在单个原子上**：方向性位移（下面单独说）+ cutoff 抖动（`U[cutoff ± 1.5]`）+ 整残基 dropout。随机丢原子会在口袋壁上打洞，同一个复合物在不同 epoch 学到的立体场就不自洽了。验证和推理用确定性的那层壳。

### 扰动参考配体（`dir_noise` + `rot_noise`）

不扰动时，壳的边界在 ~1 Å 尺度上描出了配体的轮廓 —— 模型可以直接从口袋形状把答案读出来。所以外壳不是按真实参考配体选的，而是按**绕自身质心旋转 + 刚体平移过的**参考配体选：

- 旋转 `θ ~ U[0, rot_noise]`，轴方向球面均匀
- 平移 `|u| ~ U[0, dir_noise]`，方向球面均匀

两个都是**上界**不是固定值（均值约一半），这样模型能同时见到口袋定义很准和很差的情况。

实测（10 个示例复合物 × 30 次采样）：

| 设置 | 原子数 | 残基集合变化 | 真实壳召回 | 口袋质心离配体质心 | 主轴 vs 配体 |
|---|---|---|---|---|---|
| 不扰动 | 237 | 0% | 97% | 2.21 Å | 28° |
| 平移 2 Å | 239 | 16% | 91% | 2.44 Å | 30° |
| 平移 4 Å | 242 | 30% | 85% | 3.03 Å | 31° |
| 旋转 30° | 240 | 15% | 92% | **2.11 Å** | **32°** |
| 旋转 60° | 243 | 26% | 87% | **2.05 Å** | **39°** |
| **默认 2 Å + 30°** | 242 | 24% | 88% | 2.29 Å | 34° |

**两者分工互补，所以都要**：平移把口袋推离配体（2.21→3.03 Å）但基本不转它（28→31°）；旋转转动它（28→39°）而因为是绕参考自身质心转，完全不移动它。原子数始终 237–243，预算不受影响。（主轴那几个数是总体平均，方差很大 —— 紧口袋里一个小而对齐的配体，被平移一下主轴也会动很多。）

**`rot_noise` 为什么是 30° 而不是随机旋转。** 同样是"训练分布要对上推理分布"：推理时的参考配体是真实结合在这个位点的分子，它沿着那道沟躺着，所以角度差是个小角分布而不是均匀分布。两个共享同一道沟的配体差约 20–40°。再往上不是更真实，而是朝错的方向偏出分布，而且有代价 —— 旋转 90° 的参考有 47% 的原子埋在蛋白重原子 2.5 Å 内，于是它周围的壳是蛋白内部，1/4 的真实口袋衬里被挤掉。（一个几何细节：180° 的解耦程度**不如** 90° —— 细长分子绕垂直轴转 180° 基本是它自己翻个头。）

**它同时在合成交叉对接。** 推理时参考配体离查询配体的真实位姿就是几 Å、几十度 —— 旋转平移过的真配体正是这个分布。所以不需要真实的交叉对接数据就能把那个输入分布造出来。

**接触核心故意不扰动。** 那 15 个残基是信号本身；它泄漏的是"配体的大致位置经 4 Å 膨胀后的轮廓"，而结合位点的位置本来就是任务的合法输入，而且已经通过 `pocket_com` 明确给了模型。

### 为什么不用球

把区域改成"中心 + 半径 R 的球"能彻底去掉形状泄漏，但实测代价太大：一个刚好装下 4 Å 核心残基的球要 **13.9 Å 半径 / 493 个原子**（最大 16.9 Å / 782 个），装下 6.5 Å 整壳要 **16.6 Å / 795 个**（最大 19.5 Å / 1076 个），而贴配体的壳只要 243 个 —— **同样的接触残基，球要花 2–3.3 倍的原子，其中 68%（50–84%）离配体超过 6.5 Å**。根本原因是配体细长、区域需要各向异性，而球是等向的。

## Flow Matching

| | |
|---|---|
| 路径 | `x_t = (1−t)·x_0 + t·x_1`，t=1 是真实位姿 |
| 先验 | `x_0 ~ N(口袋中心, 4² Å²)`，中心抖动训练 1 Å / 采样 0.25 Å |
| 预测目标 | `x̂_1 = E[x_1 \| x_t]`，速度 `v = (x̂_1 − x_t)/(1−t)` |
| 损失 | 坐标 MSE（Å²，即每个复合物的 RMSD²）+ `t > 0.75` 时对真实距离 < 3 Å 的原子对（键长、键角）加距离损失 |
| 采样 | 20 步 Euler ODE，最后一步正好落在 `x̂_1` 上；口袋编码缓存复用 |

**口袋中心（`pocket_com`）**：参考配体 6 Å 以内**蛋白重原子**的质心，和 SigmaDock 的 `extract_pocket_com` 一致 —— 不是参考配体自己的质心。模型是平移等变的（主干只看距离，输出头只输出相对向量），绝对坐标进不了网络，所以中心**只**通过先验起作用；要训练和推理一致的，是"先验中心到真实配体质心"这个偏移的**分布**。

用配体质心做中心会破坏这个一致性：重对接训练时它就是答案的质心，模型不需要学平移；到推理时中心偏出几 Å，模型就系统性地平移不足。口袋质心在 10 个示例复合物上离真实配体质心 1.7 Å（0.8–3.5 Å），是一个真要去解的平移；抖动则负责把推理时的中心误差覆盖进训练分布，所以采样时也保留（0.25 Å）而不是关掉。

诊断用 **`centroid_err`**（`flow.centroid_error`）：训练指标和 `val/centroid_err_median` 都有。它是唯一能暴露先验泄漏的数 —— 如果重对接上它趋近 0 而交叉对接上明显变大，说明模型在从先验里读答案，而总 RMSD 会把这件事藏起来。

## 使用

```bash
pip install -e ".[test]"        # 在 pocketdit/ 目录下
```

**1. 预处理**：每个复合物只用 RDKit 解析一次，存成 `.pt` 文件。目录结构与 PDBBind 相同，每个复合物一个子文件夹：

```bash
python -m pocketdit.data --root data/pdbbind/refined-set --out cache/train \
    --protein_glob "*_protein.pdb" --ligand_glob "*_ligand.sdf" --pocket_cutoff 15
python -m pocketdit.data --root data/pdbbind/core-set --out cache/val
```

`--pocket_cutoff` 是**缓存**的最宽壳，不是训练用的口袋 —— 预算裁剪在加载时做，所以改预算、改 cutoff 抖动、改扰动强度都不需要重跑预处理，只要缓存半径够（默认 15 Å 覆盖了默认 crop 下全部 10 个示例复合物，它们需要 12.4–14.1 Å）。`--com_cutoff` 决定先验中心取哪一层壳的质心（默认 6 Å）。

⚠️ 用完整蛋白（`*_protein.pdb`），**不要**用 PDBBind 自带的 `*_pocket.pdb` —— 那本身就是"配体 10 Å 以内"的裁剪，形状泄漏在文件层面就固化了，后面怎么裁、怎么加噪声都救不回来。

也可以用 `--csv index.csv`，列为 `protein,ligand[,ref]`，路径相对于 CSV 所在目录。交叉对接时用 `--ref_glob` 指定参考配体，由它来定义口袋。解析失败的复合物会记录在 `<out>/failures.txt`。

**2. 训练**：`TrainConfig`、`ModelConfig`、`FlowConfig`、`PocketCrop` 的每个字段都是命令行参数。

```bash
python -m pocketdit.train --train_dir cache/train --val_dir cache/val --out_dir runs/exp1 \
    --batch_size 16 --lr 3e-4 --max_steps 200000 --model.dim 256 --model.depth 6 \
    --crop.max_atoms 256 --crop.core_cutoff 4 --crop.cutoff 6.5 \
    --crop.dir_noise 2 --crop.rot_noise 30 --crop.cutoff_jitter 1.5 \
    --flow.prior_std 4 --flow.center_noise 1.0
```

日志写到 `runs/exp1/log.jsonl`。验证时用 EMA 模型报告 loss、采样 RMSD 中位数、RMSD < 2 Å 的比例和质心误差中位数。`--resume runs/exp1/last.pt` 可以断点续训。

**3. 对接**：

```bash
# 重对接（口袋由配体自身坐标定义）
python -m pocketdit.dock --ckpt runs/exp1/last.pt --protein p.pdb --ligand l.sdf --num_samples 10
# 交叉对接 / 实际使用：用参考配体或口袋中心定义口袋
python -m pocketdit.dock --ckpt runs/exp1/last.pt --protein p.pdb --ligand query.sdf --ref ref.sdf
python -m pocketdit.dock --ckpt runs/exp1/last.pt --protein p.pdb --ligand query.sdf --center 12.3 4.5 -7.8
```

口袋预算和先验设置都存在 checkpoint 里，推理会自动复现训练时的口袋，不需要重复传参（`--max_pocket_atoms` 可以覆盖）。两种定义口袋的方式里**参考配体更可靠**：`--center` 只给一个点，口袋只能是绕它的一个球（`--center_margin` 默认 6 Å，约一个配体半径），而不是贴着一个合理配体的壳。

每个复合物输出 `docked/<name>.sdf`，包含 `--num_samples` 个位姿，**未排序**。属性 `rmsd_to_input` 是相对输入坐标的对称性校正 RMSD，只在重对接时有意义。

## 刚性片段分解（`fragment.py`）

当前模型是全原子扩散。`fragment.py` 是片段化版本的第一块，**还没有接入模型**，可以单独跑来看统计：

```bash
python -m pocketdit.fragment --root data/pdbbind/refined-set --selection compact
python -m pocketdit.fragment --smiles "CCc1ccccc1" "COc1ccccc1"   # 快速查看单个分子
```

做法：切开所有可旋转键，然后在保持每个片段刚性的前提下尽量把切口合并回去。判定刚性时只看片段子图——一条在整个分子里可旋转的键，切断之后往往因为一侧没有重原子邻居而不再是扭转键，这正是合并能成立的原因。`selection` 控制合并顺序：`compact`（确定性，推理用）、`random`（训练用增强）、`none`（消融）。

几个在实现过程中确认下来的结论：

- **最小片段尺寸是最终状态的性质，不是逐步不变量。** 十碳烷切开 7 条扭转键会一次隔离出 6 个单原子，任何单步合并都只能救回一个，所以逐步卡最小尺寸会把所有合并都拒掉。只有刚性约束逐步生效。
- **2 原子片段无法避免，而且很常见。** 甲氧基、乙基、羟甲基、硫甲基都挂在分子唯一的可旋转键上，切完必然是 2 个原子。这类片段绕自身轴的旋转不改变任何原子坐标，所以它有 5 个真实自由度而 SE(3) 给了 6 个；多出来的那一维是 gauge 冗余而不是信息缺失，必须由做刚体拟合的那一方在数值上定住（`is_collinear` 负责标记）。
- **合并保护不了手性中心。** 四面体中心至少有 3 个重原子邻居，所以它自己的刚体块已经超过豁免尺寸，而且相邻扭转键两侧都还留着邻居，这条键在任何合并下都会存活。结论是立体中心相邻的扭转键一定被切开，手性只能交给模型通过 `chem.chirality_reference` 的有向体积特征处理——和全原子模式完全一样。
- 合并顺序是贪心的，不是最优的。两个启发式（填满到豁免尺寸、优先合并最小片段）各有死角且互不支配，所以两个都跑，按"先避免孤立原子、再比片段数"取优。

10 个 Astex 配体上的数字（平均 26 个重原子、6.4 条扭转键）：

| | `none` | `compact` |
|---|---|---|
| 平均片段数 | 7.4 | 5.4 |
| 合并掉的切口 | 0 / 64 | 20 / 64 |
| gauge 退化片段占比 | 54.1% | **16.7%** |

## 全量 PDBBind 上的实测（19,112 个配体，`selection=compact`）

数据 `PDBBind_processed` 19,119 个复合物，7 个 SDF 无法解析（kekulize 失败，`.mol2` 也读不出来），成功 **19,112** 个、630,125 个重原子、139,896 个片段、200,088 条扭转键。

| | `none`（10 个 Astex） | `compact`（10 个 Astex） | `compact`（全量 PDBBind） |
|---|---|---|---|
| 平均片段数 | 7.4 | 5.4 | **7.32** |
| 合并掉的切口 | 0 / 64 | 20 / 64 | **79,306 / 200,088（39.6%）** |
| gauge 退化片段占比 | 54.1% | 16.7% | **23.5%** |

**23.5% 而不是 15%。** 拆开看：其中 23.4 个点是 ≤2 原子片段，真正的"≥3 原子但共线"（腈基那类）只有 0.1%（104 个），1 原子 5 个。这个数**不是由某几个分子撑起来的**（最极端的 316 个分子才占全部退化片段的 25%），但**随分子大小单调上升**，从 19% 涨到 35%：

| 重原子数 | 分子数 | 片段/分子 | 退化占比 | 平均扭转键 |
|---|---|---|---|---|
| ≤ 50（占 87.9%） | 16,796 | 5.22 | **19.0%** | 6.51 |
| 51–100 | 1,802 | 19.16 | 29.0% | 32.92 |
| > 100 | 514 | 34.29 | 35.0% | 60.96 |

10 个 Astex 配体平均 26 个重原子、7.4 条扭转键，正好落在第一档的**左端**；那一档的真实期望是 **19%，比 16.7% 高不了多少**，所以"15% 上下"没被证伪。23.5% 是被 12% 的柔性大分子（肽、大环）拉上去的。它们进不了模型——扭转键 p90 就已经 24、p99 68，远超 `--max_torsions` 的 20（11.8% 的配体超这条线，这还不算片段和口袋的显存）。

**扭转键分布**（每条分子）：mean 10.47、median 6、p75 11、p90 24、p95 41、p99 68、max 110。药芯子集（≤50 原子）的 p25/p50/p75/p90/p95/p99 = 3 / 6 / 8 / 13 / 16 / 24。切开的 60.4% 是软关节，合并回的 39.6% 变刚性。真正被 `_mergeable` 排除的只有 ring–ring 桥键和"两端旋转度都为 1"的末端键——这类键**没有更优解**，任何合并都会让片段内部保留扭转。

`ignore_conjugated=True` 会再砍掉 14.1% 的扭转键（每条分子平均 1.47 条），把切口占比推到 69.0%。

复现：`python scripts/fragment_sweep.py --root <...> --out sweep.csv` 再 `python scripts/analyze_sweep.py sweep.csv`；单分子为什么被切可以看 `python scripts/diagnose_merge.py --root <...> --name 2rqu`。

## 片段的 SE(3) 目标（`rigid.py`）

`fragment.py` 决定在哪里切，`rigid.py` 决定每一块该去哪里。片段模式下位姿不是 3N 个坐标，而是每个片段一个刚体变换：片段内部几何取自输入构象、全程不动，剩下的自由度只有 SE(3) 里的 `(R_f, t_f)`。同样**还没有接入模型**，可以单独跑来看数字：

```bash
# 整个数据集，模板用新嵌的 ETKDG 构象
python -m pocketdit.rigid --root data/pdbbind/refined-set --template etkdg
# 模板用复合物自带的起始构象（推理真正拿到的那个几何）
python -m pocketdit.rigid --root ../notebooks/dummy_data --template "*_ligand_start_conf.sdf"
# 单分子：每个片段的拟合残差、转角、等价解个数
python -m pocketdit.rigid --smiles "CC(C)(C)c1ccc(OC)cc1"
```

三件事决定目标是什么。

### 目标是对齐后的模板，不是真实位姿

片段内部几何来自输入构象，它和晶体位姿的内部几何不一样——键长差几个百分之一 Å，键角差一两度。所以没有任何刚体摆放能精确复现晶体坐标，**朝晶体位姿回归等于让模型去追一个它到不了的点**，并且在损失里留下一个训练永远消不掉的地板。目标取能够到的那个最近的摆放，也就是模板片段到真实片段的 Kabsch 拟合：最优解变成可达的，残差被单独报出来（`FragmentTargets.rmsd`）当作参数化的代价，而不是藏在损失里的偏置。

10 个 Astex 配体 / 54 个片段，模板用各复合物自带的 `*_ligand_start_conf.sdf`：

| | 个数 | 拟合残差 平均 / 中位 / 最大 |
|---|---|---|
| 芳环 | 21 | 0.037 / 0.038 / 0.069 Å |
| **饱和环** | **3** | **0.348 / 0.398 / 0.451 Å** |
| 非环 | 30 | 0.032 / 0.018 / 0.114 Å |
| 整条分子的位姿 RMSD | 10 | **0.089 / 0.052 / 0.232 Å** |

**地板几乎全部来自饱和环。** 54 个片段里只有 3 个，但它们的残差比别人高一个数量级，而且位姿 RMSD 最差的三个复合物（1MZC 0.232、1YQY 0.210、1S3V 0.131）正好就是带饱和环的那三个。原因很直接：环内没有可旋转键，所以 `fragment.py` 把整个饱和环当成一块刚体，但它的**褶皱（chair / boat / half-chair）是真实存在的构象自由度**——模板把它定死了，刚体拟合再也救不回来。芳环和非环片段只差键长键角，都在 0.04 Å 量级。换成新嵌的 ETKDG 构象，整体从 0.089 升到 0.107 Å，分布形状不变。

所以片段参数化的代价不是"内部几何不准"，而是"饱和环的构象被冻住"。要往下压就得给环单独一条路（枚举环构象，或者把环内自由度交回模型），调拟合是没用的。

切口两端的键长也值得看一眼：片段各自独立拟合，没有任何东西把一条被切开的键按在成键距离上。实测平均 0.045 Å、最大 0.171 Å（ETKDG 模板下 0.059 / 0.547 Å），`joint_errors` 负责报它。

### 等价解：对称与共线，都取最近的那个

拟合不唯一，而且有两种不唯一，都必须定下来，否则目标是任意的。

**对称。** 如果分子分不出片段里的两个原子——单取代苯环的两个邻位碳、同一个氮上的两个甲基——那么交换它们是同一个化学对象的另一种标号，于是"把模板拟合到交换后的真实位姿"就是另一个候选变换。所有这样的标号都被枚举、都做拟合，取拟合最好的那个。唯一的硬约束是**跨切口成键的原子必须不动**：它们是相邻片段的锚点，而相邻片段各自独立拟合，动了就会让组装出来的目标在那个关节上拉出一根拉伸的键。（顺带的好处：切口两端的原子因此从不被重标号，上面那个关节长度才能逐原子地比。）

分出来的两类行为完全不同：

- 标号变换恰好是**模板的一个旋转**（单取代苯环绕 ipso–para 轴翻 180°）时，它和恒等标号拟合得**必然一样好**——此时"重标号"和"旋转"是同一件事。这些是真正的平局，`reference` 就是用来破平局的。
- 标号变换只是模板的一个**镜像**时，它是另一个位姿，拟合通常差很多——而这恰恰是不能把它过滤掉的理由。叔丁基的三个甲基等价，所以它的标号绕自身轴可以顺时针也可以逆时针走，而同一个分子的两个构象经常就是不一致的。4-叔丁基苯甲醚的两个 ETKDG 构象上，恒等标号把叔丁基拟合到 **0.45 Å**，镜像标号是 **0.05 Å**，整条分子的目标从 0.26 Å 降到 0.03 Å。**片段是非手性的，它的标号才是手性的**；坚持用恒等标号等于无缘无故地要求模型去对一个偏 0.4 Å 的位姿。

（这是实现里最容易做错的一步。第一版只收"真旋转"的标号，看着干净得多——然后叔丁基的残差就停在 0.45 Å。`is_template_symmetry` 现在只用来区分这两类、给统计用，不再当过滤器。）

**共线（gauge）。** 两原子片段或共线片段绕自身轴旋转不改变任何原子坐标，所以一整圈旋转给出完全相同的坐标——就是 `fragment.is_collinear` 报的那个多余自由度。Kabsch 没法在它们之间选：协方差矩阵降秩，SVD 返回哪一个全看数值，既不跨机器可复现、也不随输入连续。单原子片段整个 SO(3) 都是自由的。这一自由分量被定到**离参考最近**的那个旋转上（默认参考是单位矩阵，也就是模板自己的坐标系），坐标一点不变，但旋转目标变成位姿的一个良定义、连续的函数。10 个配体上 **16.7% 的片段**要定这个 gauge——和 `fragment.py` 报的 compact 退化占比完全一致，两边是互相独立算出来的。

于是：**目标函数是拟合，平局才用"最近"来破**，`tie_tol` 决定多近算平局。真旋转的对称精确平局，gauge 那一圈按构造完全平坦，所以"最近"恰好决定了拟合**看不见**的全部、也只决定这些。`pairing` 记录每个目标原子是拟合到哪个真实原子上的，逐原子损失因此和选中的标号始终自洽。

`reference` 同时是接入 flow 的那个口子：训练时每个片段有一个当前的 `R_t`，flow 该走的测地线通向**最近**的那个等价目标，而不是某个固定代表元，否则对称片段会被赶着绕自己的对称群走一大圈。传 `reference=R_t` 就是这个意思，`pin_gauge` 和标号选择都会跟着它。

### ≤ 50 原子的过滤

上面全量 PDBBind 的表在 50 个重原子处分得很干净：≤ 50（占 87.9%）平均 5.22 个片段、6.51 条扭转键、19.0% gauge 退化；往上是 19–34 个片段、33–61 条扭转键、29–35% 退化。那些是肽和大环，光扭转键（p90 24、max 110）就已经超出模型 `--max_torsions 20` 的尺度，为它们算片段目标是给一个训不了的复合物白做功。所以 `MAX_LIGAND_ATOMS = 50` 是硬上限：超了 `fragment_targets` 直接抛错（`max_atoms=None` 关掉），统计和命令行把它们单独计数而不是悄悄跳过。

**过滤的是配体，不是片段。** 丢掉大配体里几个难办的片段会留下一个拼不起来的位姿，所以只能整条丢。这和 `data.py` 的 `--max_atoms`（全原子模式的缓存上限，默认 128）是两件事。

### 测试

`tests/test_rigid.py`：Kabsch 精确还原刚体变换、且在任何代价下都不做镜像；目标片段的内部距离矩阵和模板逐个相同（"刚性"的定义）；模板等于真值时精确命中、残差 0；模板是另一个构象时残差 > 0（地板存在）且优于把整条分子当一块刚体；扰动任何片段的变换只会更差（拟合在最优点）；参考跟着位姿一起转时整个目标严格等变；`embed_template` 不翻手性。gauge：定 gauge 不动任何原子、两原子片段拿到的就是绕 a×b 的最小旋转、同一圈里任何成员都定到同一个代表元、单原子片段直接拿参考、gauge 标记与 `is_collinear` 一致。对称：单取代苯环恰好 2 个标号且 ipso/para 是不动点、叔丁基 6 个标号里 3 个是真旋转且镜像那个救了拟合、跨切口原子从不被重标号、真旋转标号给出同一个位姿且残差相同、平局里取的确实是最近的、把参考指向某个解就能选中它。还有 ≤ 50 原子的上限正好在原子数上生效。

## 已知局限和下一步

- **还没有在真实数据集上训练过**，没有 benchmark 数字。默认超参数（先验 4 Å、预算 256、cutoff 抖动 1.5 Å、距离损失权重等）都是合理的起点，没有经过调优。`crop.shell_dropout` 默认关着：cutoff 抖动已经在动边界了，再叠一层整残基 dropout 是否有用需要实测。
- **没有置信度或打分模型**，多个采样位姿无法排序。可以加一个 confidence head，或者接 GNINA / Vina 重打分。
- 全原子模式的坐标 MSE 没有处理**对称等价原子**（例如羧基的两个 O、对称苯环），评估时请用对称性校正的 RMSD（`dock.py` 中已用 RDKit `CalcRMS`）。片段模式不受影响：`rigid.fragment_relabellings` 在片段层面枚举了这些等价标号，目标本身就是对称校正过的。
- **形状泄漏还剩一项**：4 Å 核心的轮廓（故意保留，见上）。外壳的细轮廓被 `dir_noise` 打散，拉伸方向被 `rot_noise` 转开，中心泄漏靠 `pocket_com` 堵住。还剩多少值得用 `centroid_err` 的重对接/交叉对接差值去量。
- **还不是"盒子无关"的通用对接程序。** 现在的输入模式是"参考配体定口袋"（SigmaDock 式的 `--autobox`），参考配体扰动把这个模式的训推分布对上了。要支持"给一个中心 + 半径的盒子"还缺三样：训练时随机化 (中心偏移, R) 并把 R 作为标量 conditioning 喂进 `c`；先验拆成分子级共享平移 + 局部抖动（现在 `x_0` 的质心只在 1.26 Å 内变动，`σ/√n` 压着，所以多个样本的落点几乎重合、根本不探索区域）；以及跨中心排序所需的 confidence head。
- 先验是逐原子独立的高斯，原子间距期望约 9.8 Å，比真实分子散得多；harmonic prior（按键图的拉普拉斯构造先验）应该更贴。
- **片段参数化只做完了目标那一半。** `fragment.py` + `rigid.py` 已经能把一个复合物变成"每个片段一个 SE(3) 目标"，剩下的是模型侧：输出头不变，把逐原子向量聚合成片段的力和力矩；`x_t` 改成每个片段一个当前变换（于是 `rigid` 的 `reference` 接 `R_t`）；损失从坐标 MSE 换成平移 + 旋转（测地线或 chordal）。预处理也要存 `frag_idx` 和模板构象。地板已经量过：饱和环之外是 0.03–0.04 Å，饱和环要单独处理（见上）。
- 其他可尝试的扩展：self-conditioning、非均匀的 t 采样和时间步长。
